# Aurelia Motor Co. – Group Website Project

## 1. Project Overview

Aurelia Motor Co. is a fictional premium automotive business. We are creating a professional, responsive five-page website for our Web Development Fundamentals group assignment.

Our website introduces the company, presents its services, and allows visitors to learn about the business, contact us, and submit a vehicle request.

We are using HTML5 and CSS3 to build the website. The project focuses on front-end development, including website structure, design, navigation, responsiveness, and HTML forms.

## 2. Website Pages

Our project includes five connected pages:

- **Home (`index.html`):** Introduces Aurelia Motor Co. and welcomes visitors to the website.
- **About (`about.html`):** Explains who we are, our business, and what makes our company different.
- **Services (`services.html`):** Presents the automotive services offered by the company.
- **Contact (`contact.html`):** Provides information about contacting the business and includes a contact form.
- **Registration (`registration.html`):** Allows visitors to submit a vehicle request and provide their preferences.

All five pages share the same general design, navigation, colors, fonts, and layout to create a consistent experience.

## 3. Our Development Work and Improvements

We used GitHub Copilot to help us get started with the website structure and initial code. However, the generated website was not our final version.

After generating the initial pages, all three group members worked together to review, edit, and improve the website. We made changes to the individual HTML pages, corrected mistakes, improved the content, updated the styling, and made sure the pages worked together as one complete website.

Our improvements included:

- Reviewing and editing all five HTML pages.
- Correcting HTML mistakes and improving the page structure.
- Updating text and content to better represent Aurelia Motor Co.
- Improving the website's overall appearance and layout.
- Updating the CSS to make the design consistent across all pages.
- Improving navigation and checking links between pages.
- Adjusting spacing, colors, fonts, and other styling details.
- Improving the website's responsiveness for different screen sizes.
- Reviewing images, image paths, and alternative text.
- Checking the forms and making improvements to their HTML elements.
- Testing the website and fixing problems we discovered.

We shared the work as a group and reviewed each other's changes to make the final website more complete and professional.

### Registration Form Improvements

We improved `registration.html` by adding more HTML form elements to meet the assignment requirements.

Our registration form includes:

- Full name field with required and length validation.
- Email input with browser validation.
- Phone number input with pattern validation.
- Select menu for choosing an area of interest.
- Datalist with suggested vehicle types.
- Number input for estimated budget, with minimum and maximum values.
- Date input for the preferred appointment date.
- Textarea for additional information.
- Radio buttons for the preferred contact method.
- Checkbox for receiving updates.
- Fieldsets and legends to organize form sections.
- Submit and reset buttons.
- Required fields and other HTML validation attributes.

### CSS Improvements

We also worked on `styles/styles.css` to improve the overall design and support the different elements used throughout the website.

Our CSS includes:

- Consistent colors and fonts.
- Navigation and header styling.
- Responsive page layouts.
- CSS Grid and Flexbox.
- Styling for service cards and content sections.
- Contact and registration form styling.
- Media queries for smaller screens.
- Spacing, alignment, and layout improvements.

Our goal was to make all five pages look like parts of the same professional website rather than separate pages.

## 6. How We Work Together Using GitHub

We use GitHub to organize our work, share updates, and make sure every group member can contribute to the project.

Our group workflow includes:

- Each team member works on their own branch.
- We avoid making changes directly to the `main` branch.
- We commit and push our work regularly.
- We use Pull Requests to submit changes for review.
- We review each other's code before merging changes into the main project.
- We pull the latest changes before continuing our work.
- We communicate with each other when making changes to shared files.

This workflow helps us avoid losing work, keeps our project organized, and allows us to work together more easily.

## 7. How We Use GitHub Copilot

We use GitHub Copilot in Visual Studio Code as a coding assistant throughout the project.

Copilot helps us generate ideas, understand HTML and CSS, find errors, and improve existing code. We also use it to review our pages and check whether we are meeting the assignment requirements.

Some examples of prompts we use include:

**Review HTML pages:**

"Review this HTML page for errors, missing elements, accessibility problems, and broken links. Keep the code simple and beginner-friendly."

**Improve the website design:**

"Review our CSS and make sure the website looks consistent and responsive on desktop, tablet, and mobile. Keep the existing Aurelia Motor Co. design."

**Check the forms:**

"Review our contact and registration forms against the assignment requirements. Check labels, fieldsets, legends, input types, validation, radio buttons, checkboxes, datalists, and submit and reset buttons."

**Check navigation:**

"Check that all five pages are connected correctly and that every navigation link works."

**Find and fix errors:**

"Check this page for HTML and CSS errors. Fix broken links, incorrect file paths, missing attributes, and layout problems without changing the overall design."

**Improve existing code:**

"Review our existing code and suggest improvements. Keep the same website design and make sure the changes work with the other pages."

We do not simply accept everything Copilot generates. We review the suggestions, make our own changes, correct mistakes, and test the code before including it in the final project.

## 9. Forms and Project Limitations

Our forms demonstrate front-end HTML form functionality and browser validation.

They allow visitors to enter information and test the different form elements. However, the website does not save information to a database, send emails, or process requests through a server.

These features would require back-end development, which is outside the scope of our assignment.
